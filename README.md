# npfl087-otmara

Code for the NPFL087 project on **detecting bad translations with perplexity**.
LLMs translate English source sentences into Czech, both properly and badly (or
the translations are damaged afterwards), and a panel of other LLMs ("raters")
then measures the perplexity of every translation. The question is how well
those perplexities, from one rater or from an ensemble, tell the good
translations from the bad ones.

## What is *not* in this repository

Three things the pipeline needs are deliberately left out. You have to get
them yourself and put them **next to** this repository, not inside it. Every
script is run from inside `npfl087-otmara/` and reaches them through `../`.

| what | why it is missing | where it goes |
|---|---|---|
| the deprefset data: the many-references datafile and the WMT `deprefset` system outputs | too big (the datafile alone is ~2.6 GB) | `../many-references-datafile` and `../WMT_data/deprefset/en-cs/*.jsonl` |
| the HuggingFace token | private | `../token` |
| the SLURM/PBS job directories `jobs/`, `job20/`, `job30/`, `job40/` | full of absolute paths that only exist on the cluster this was run on | `../jobs/`, `../job20/`, `../job30/`, `../job40/` |

More detail on each:

- **Many-references datafile.** This is *Many Czech References for 50 Sentences
  Selected from WMT11 Data* (Bojar, Macháček, Tamchyna, Zeman; TSD 2013), which
  contains 15.4M Czech reference translations of 50 English WMT11 sentences.
  Download `many-czech-references.zip`, unpack it, and put the uncompressed
  tab-separated `many-references-datafile` at `../many-references-datafile`.
  `python/buildDeprefGood*.py` reads it to build the `deprefGood*` classes.
- **WMT deprefset system outputs.** These are one JSONL file per MT system (27
  systems, 50 sentences each, with the candidate in the `hypothesis` field).
  Put them in `../WMT_data/deprefset/en-cs/`. `python/buildDeprefsetSystems.py`
  reads them to build `resources/output40/`.
- **HuggingFace token.** Create a token at huggingface.co, accept the licences
  of the gated models you want to use (Llama, Gemma, Aya, Command R, ...), and
  write the token as the first line of `../token`. `python/hftoken.py` reads it
  from there.
- **Job directories.** These are only submission wrappers around the Python
  scripts below. They are generated by `job20/makejobs20.py`,
  `job30/makejobs20.py`, `job40/makejobs40.py`, `jobs/makeCVShardJobs.sh` and
  `jobs/makePerpShardJobs.sh`. If you have a copy, put it next to the repo and
  change `/storage/praha1/home/tondaotm/npfl087` to your own root. Otherwise
  call the Python scripts directly, as shown below.

The scripts also need these things, which are not part of the repo either:

- a Python 3.11 virtualenv at `../v/` with `torch`, `transformers` 5.7.0,
  `accelerate`, `optimum-quanto`, `kernels>=0.12,<0.13` (needed for `gptoss`),
  `numpy`, `scipy` and `matplotlib`. The bash
  wrappers call `../v/bin/python3.11`.
- MorphoDiTa and its dictionaries, for the morphological corruption:
  `../morphodita-1.11.3-bin/`, `../czech-morfflex2.1-pdtc2.0-250909/` and
  `../english-morphium-wsj-140407/`, all from LINDAT/ÚFAL.

The generated data is not committed either. `output20/`,
`resources/output20/`, `resources/output30/` and `resources/output40/` are in
`.gitignore` because they hold hundreds of MB of model output and
perplexities. The scripts below regenerate them, and they create the files in
those directories.

### Prompt paths

The generation and corruption scripts read their few-shot prompts from fixed
paths under `./resources/prompts/`. You can point these paths at any file, so
you can swap in your own prompts (a different language pair, different
examples, a different kind of damage):

| script | prompt it reads |
|---|---|
| `generateTranslations.py` | `en_to_cs.txt` / `cs_to_en.txt` |
| `generateBadTranslations.py` | `en_to_cs_wrong.txt` / `cs_to_en_wrong.txt` |
| `corruptSentencesLLM.py`, `corruptSentencesLLMfromraw.py`, `corruptSentencesLLMAnswerOnly.py` | `corrupt_cs.txt` |
| `corruptSentencesLLMTriple.py`, `corruptSentencesLLMtriple.py` | `corrupt_cs3.txt` |
| `corruptToFakeRealPrompt.py` | `en_to_cs.txt` |
| `bash/separateCorruptedTriple.sh` | `en_to_cs_single.txt` |

`corrupt_cs3.txt` asks for three corruptions of each sentence in a single
answer, which then has to be split up by `bash/separateCorruptedTriple.sh`.
Instead of that triple prompt, you can run the single-corruption prompt
`corrupt_cs.txt` three times with different random seeds. Each corruption is
then its own clean answer, and no splitting is needed. Most `get<model>.py`
files decode greedily, so for a different seed to give a different output,
first turn on sampling in that model's `promptModel()` (`do_sample=True`, as
in `getnandi.py`). Then set the seed before generating, e.g. with
`transformers.set_seed(seed)`.

## Running

Run everything from this directory with the virtualenv:

```bash
cd npfl087-otmara
../v/bin/python3.11 ./python/<script>.py <args>
```

## Data format

Every class file is a sequence of units in this format:

```
prompt:
<few-shot prompt + source sentence>
answer:
<translation>
-----------------------------
```

The perplexity scripts score only the `answer` part.

## Repository contents

### `resources/`

Only the source texts and prompts are committed. `bad/`, `out/`, `metrics/`,
`misc/`, everything in `good/` except `cs.txt` / `en.txt`, and the `output20/`,
`output30/` and `output40/` directories are in `.gitignore`. The table shows
the layout the scripts write.

| path | contents |
|---|---|
| `en.txt_unchanged`, `cs.txt_unchanged` | the 50 English sources and their Czech WMT references |
| `prompts/` | few-shot templates: `en_to_cs.txt` / `cs_to_en.txt` (correct), `*_wrong.txt` (deliberately wrong examples, for the `bad` class), `corrupt_cs*.txt` (for LLM corruption) |
| `good/`, `bad/`, `out/`, `metrics/`, `misc/` | early (output10/20) generated data, raw pipeline output and metrics (`good/cs.txt`, `good/en.txt` are committed, the rest is not) |
| `output20/` | the second round of experiments |
| `output30/<class>/<model>.txt` | the main dataset, one file per class and generating model (see below) |
| `output30/perps/by<rater>/<class>/of<model>.txt` | perplexities, one number per unit |
| `output30/*.csv`, `output30/graphs/` | scoring results, used in the papers |
| `output40/` | real WMT systems: `deprefset/<slug>.txt`, `systems.tsv` (slug → system name), `perps/` |

Quality classes in `output30/`:

- `good`: the model's own translations (the positive class)
- `bad`: its translations made with the wrong few-shot prompts
- `broken`: its `good` answers corrupted morphologically with MorphoDiTa
- `corrupt` / `corruptTriple`: the model's LLM corruption of the gold
  references (one, or three, corruptions per sentence)
- `candidateCorrupt`: the model's LLM corruption of its own `good` answers
- `deprefGood`, `deprefGoodMedium`, `deprefGoodBig`, `deprefGoodBigger`: human
  references from the many-references datafile, 39 / 200 / 1000 / 5000 per
  sentence, in one `all.txt` per class
- `deprefBroken`, `deprefBrokenMedium`: `deprefGood` and `deprefGoodMedium`
  corrupted with MorphoDiTa

### `python/`

**Models**
- `get<model>.py`: each one exports `getModelAndTokenizer()` and
  `promptModel(model, tokenizer, role, prompt)` for one HF model (`qwen`,
  `llama`, `gptoss`, `gemmabig`, `aya`, `ayaexp`, `commandr`, `eu`,
  `mistral7b`, `dolphin`, `darwin`, `ibm`, `tower`, ...)
- `modelMap.py`: maps short names to those functions (`model_map`,
  `prompt_method_map`)
- `hftoken.py`: reads `../token`

**Generating the classes**
- `generateTranslations.py <model> <file> <src> <tgt>`: `good` translations
- `generateBadTranslations.py <model> <file> <src> <tgt>`: `bad` translations
  (`*_wrong.txt` prompts)
- `corruptSentencesLLM.py`, `corruptSentencesLLMTriple.py` /
  `corruptSentencesLLMtriple.py`, `corruptSentencesLLMfromraw.py`: LLM
  corruption of the gold references (`corrupt`, `corruptTriple`)
- `corruptSentencesLLMAnswerOnly.py <model>`: `candidateCorrupt` (reads a good
  file on stdin, replaces each answer with its corruption)
- `breakSentencesWithMD_cs_answerOnly.py`, `breakSentencesWithMD_cs_depref.py`,
  `breakSentencesWithMD_en*.py`, `breakTags.py`, `breakTagsEn.py`: MorphoDiTa
  corruption that changes gender, number, case and person (`broken`,
  `deprefBroken`)
- `buildDeprefGood.py [N] [OUT]` and `buildDeprefGood{Medium,Big,Bigger}.py`:
  the `deprefGood*` classes, built from `../many-references-datafile`
- `pruneDeprefGood.py`: cuts a built and measured `deprefGood` down to fewer
  references per sentence, without re-measuring
- `buildDeprefsetSystems.py`: `output40/deprefset/`, built from
  `../WMT_data/deprefset/en-cs`

**Cleaning model output**
- `separateAnswers.py`, `separateAnswersThinking.py` (strips `<think>`),
  `separateAnswersLimited.py`, `separateAnswersCorrupted*.py`,
  `extractAnswers.py`, `removeSpecialTokens.py`, `toSentences.py`
- `corruptToFakeRealPrompt.py`, `makeIntoPrompts.py`: rewrap corrupted
  sentences into translation-style prompt/answer units

**Measuring perplexity**
- `calculatePerplexityAnswerOnly.py <rater> <file> [--shard=I/N]`: the main
  one. It scores the answer tokens only, one unit at a time, and writes to
  `output*/perps/`
- `mergePerpShards.py <shard_dir> [out]`: merges `--shard` outputs back into
  one file, bit-identical to an unsharded run
- `calculatePerplexity.py`, `calculatePerplexityI.py`,
  `calculatePerplexity*Limited.py`: older whole-unit variants
- `checkPerpsConsistency.py`, `auditCandidateCorrupt.py`: check that every
  rater's perplexity files are complete and agree with each other

**Scoring and analysis**
- `scoreSeparation.py`, `scoreSeparationSampled.py`: AUROC of each single
  rater
- `scoreSeparationSampledEnsemble*.py`: AUROC of every rater subset. The
  variants add normalisation, log z-scoring, a train/dev split, a split by
  source sentence, `deprefGood` as the positive class, and 10-fold CV by
  source (`...CVBySentence.py`, which can be sharded with `--shard=I/N`)
- `mergeCVShards.py`: merges the CV shard CSVs
- `sourceSentenceIds.py`: labels each unit with its source sentence (needed
  for the source-level splits)
- `buildSentencePerplexityMap.py`: caches per-sentence perplexities
  (`sentenceMap.json`). Build it before the source-id map
- `ensembleCountsSampledEnsemble.py`, `raterCorrelationMatrix.py`,
  `raterDisagreementExamples.py`, `compare_similarity.py`: further analyses
- `buildPerpsCSV.py`, `buildPerpsCSV30.py`, `buildStripData.py`,
  `buildSizeCurveData.py`, `plotPerplexityDistributions*.py`,
  `plotAurocVsSampleSize.py`: tables, CSVs and figures for the papers

### `bash/`

These are thin wrappers that run the Python scripts with the venv:

- `generateTranslations.sh`, `generateBadTranslations.sh <model> <file> <src> <tgt>`
- `generateBadTranslationsMorphoDita*.sh`: the MorphoDiTa `broken` pipeline
- `corruptSentencesraw.sh`, `corruptSentencesTriple.sh`,
  `separateCorruptedTriple.sh`, `candidateCorrupt.sh <model>`: LLM corruption
- `short_bad_md_{analyze,generate}_{cs,en}.sh`: call the MorphoDiTa binaries
- `cleanBad.sh`, `cleanBadOfArg.sh`, `deleteEmptyLines.sh`, `myString.sh`:
  helpers for cleaning output

## A typical run

```bash
# 1. generate a class (here: qwen's good translations), then clean the raw
#    output with separateAnswers.py into resources/output30/good/qwen.txt
bash ./bash/generateTranslations.sh qwen resources/en.txt_unchanged en cs

# 2. measure it with a rater
../v/bin/python3.11 ./python/calculatePerplexityAnswerOnly.py llama resources/output30/good/qwen.txt

# 3. once every rater has measured every class, score the ensembles
../v/bin/python3.11 ./python/scoreSeparationSampledEnsembleNormalizedLogCVBySentence.py
```

On the cluster, steps 2 and 3 are submitted through the job directories that
are not in this repo (e.g. `bash ../job30/superjob.sh <rater> <mem>`).
